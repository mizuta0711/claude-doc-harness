## 文書ルール（harness-doc）

マニュアル・手順書・仕様書を書くときの規律。**書くより先に、読者が誰かを決める。**

1. **文書を書く前に、必ず `/harness-doc:manual-writer` スキルを使う。** 読者とゴールの決定 →
   事実確認 → 目次案 → 本文 → 自己点検 → 読者役レビュー → 機械チェック、の順で進める。
   「軽い修正だから」で飛ばさない。修正でも読者は変わらない
2. **事実は、コード・設定・実機の挙動から確認する。** 記憶や推測で書かない。
   手順に出てくるコマンドは実際に実行して、その出力を書く
3. **確認できなかった事実は、本文に「未確認」と明記する。** 断定しない。
   「未確認」が残ったままの文書は、そのことを冒頭に書いて渡す
4. **文書の完成前に、`doc-reviewer` エージェントによる読者役レビューを必ず通す。**
   指摘は全件に「対応済み／見送り（理由）」を付ける。書く役とレビューする役は分ける
5. `.md` を書くと `check-docs` フックが曖昧語・見出し・コードブロックの言語指定・用語集・
   リンク切れを検査する。**失敗したら、指摘を直してから先へ進む。** 検査を抑止するのは
   `docs-style/README.md` に書いてある場合に限る
6. 用語は `docs-style/glossary.md` に揃える。新しい用語を使うときは先に用語集へ足す。
   曖昧語は `docs-style/banned-words.txt` にある。使いたくなったら条件と値を書く

> 使い方の全体は [docs-style/README.md](docs-style/README.md) にある。
