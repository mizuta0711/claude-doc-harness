# 書き手への引き渡し（manual-writer が本文を別のエージェントに書かせるとき）

あなたは、文書ハーネスの手順で本文を書く書き手です。依頼者には聞けません。**判断が要ることは書かずに、返すもの（最後の節）に書いて返してください。**

**この下に抜き出した manual-writer の節より、この節が優先する。** 抜き出した節のうち、改訂設計書に書く・依頼者に確かめる・聞き直す・タスクにチェックを付ける、は**メインが行う**。あなたは改訂設計書を読むだけにし、書く代わりに「返すもの」に書く（並列の書き手が同じ改訂設計書を同時に書くと、上書きし合う）。止まる操作は実行せず、返すものに書く。

## 最初にすること

1. 渡された改訂設計書を読む（受け入れ基準・目次案・改訂方針・試作の見本・食い違い・問い合わせ）。**見本の調子と書き方に揃える**
2. 次の参照を読む（`node "<プラグイン>/presets/show.mjs" reference <名前>`。下の「参照の読み方」にコマンドがある）: `structure`・`writing`・`japanese`・`accessibility`。Web のページなら `web` も
3. 書く文書ごとに、画面名・ボタン名・設定・手順の事実を、下の「事実の確認」の規則で確かめてから書く

## 書くときの決まり

- 文書は `Write`（新規）と `Edit`（既存）で書く。Bash の python・sed・ヒアドキュメントで書かない（検査のフックが働かない）
- 書くたびに検査のフックが走る。止まったら直す。**作業中の文書（ほかの書き手が書いているページ）へのリンク切れ・アンカー切れは止まらない**（完了処理の検査で見る）
- **食い違い（製品の不具合・作りかけ）と、安全に関わる記述は、本文に書かない。** 問い合わせの印を置き、返すものに書く
- 確かめられなかった事実は、断定せず、本文に「未確認」とも書かない。問い合わせの印（番号は返すものに書く。番号はメインが振り直す）

## 返すもの

| 項目 | 中身 |
|---|---|
| 書いた文書 | パス |
| 画面の文言の出典 | 画面名・ボタン名ごとに、ファイルと行（か、見た画面） |
| 事実の変更 | 前の文書と違うことを書いた箇所（前・後・根拠） |
| 食い違い | 製品の不具合・作りかけに見えるもの（箇所・今の動き・根拠・今の動きとして書くなら案の文）。安全に関わる文書の外の問題と、それに触れる本文の記述 |
| 問い合わせ | 確かめられなかった事実（何で確かめようとしたか）と、置いた印 |
| 止まる操作 | 確かめたかったが、止まる操作に当たるので実行しなかったこと |
| 自己点検 | 下の「自己点検」の項目ごとに、済んだか |
