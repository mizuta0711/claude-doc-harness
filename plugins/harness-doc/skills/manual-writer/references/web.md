## 要点

1. **読者はページを読み込まず、拾い読みする。** 新しいページを拾い読みした被験者は 79%、1語ずつ読んだのは 16% だった（1997年の調査）。（出典: https://www.nngroup.com/articles/how-users-read-on-the-web/ ）
2. **文章量を減らすと使いやすさが上がる。** 簡潔にした版は 58%、拾い読みしやすい配置の版は 47%、客観的な言葉にした版は 27% 改善し、3つを組み合わせた版は 124% 改善した。推奨する分量は「従来の書き方の半分以下」。（出典: https://www.nngroup.com/articles/how-users-read-on-the-web/ ）
3. **読まれるのは本文の 20〜28% 程度。** 平均的な訪問で読める語は最大 28%、現実には約 20%。半分以上が読まれるのは 111 語以下のページだけだった。（出典: https://www.nngroup.com/articles/how-little-do-users-read/ ）
4. **視線は F 字に動く。** 最初の数行と、各行の左端にある最初の数語に視線が集中する。対策は、重要な点を最初の2段落に置く、見出しを目立たせる、見出しを情報量の多い語から始める、関連する内容をまとめる、要所を太字にする、リンク文を具体的にする、列挙と手順に箇条書きと番号を使う、余計な内容を削る、の8つ。（出典: https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/ ）
5. **結論を先に書く（逆ピラミッド）。** 最も重要な情報を冒頭に置き、詳細を後ろに続ける。読者がどこで読むのをやめても要点は伝わる。（出典: https://www.nngroup.com/articles/inverted-pyramid/ 、 https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-structure/ ）
6. **1段落に入れる考えは1つ。** 2つ目以降の考えは読み飛ばされる。（出典: https://www.nngroup.com/articles/how-users-read-on-the-web/ ）
7. **内容は小さな塊に分ける。** 短い段落を余白で区切る、本文と区別できる見出しを付ける、キーワードを強調する、箇条書きや番号付きリストを使う、長い節には要約段落を付ける。（出典: https://www.nngroup.com/articles/chunking/ ）
8. **長いページでも構わないが、道案内を付ける。** 目次、塊への分割、段階的な開示、ページ内リンクで補う。要約は冒頭に置く（末尾の要約は見つけてもらいにくい）。GOV.UK はページの長さに上限も下限もないとしている。（出典: https://www.nngroup.com/articles/formatting-long-form-content/ 、 https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/ ）
9. **太字・ハイライトは本文の 30% まで。** 最も重要な点だけを強調する。（出典: https://www.nngroup.com/articles/formatting-long-form-content/ ）
10. **見出しは内容を表し、要点を先頭に置き、動詞で始める。** 「はじめに」のような中身の分からない見出しは避ける。見出しを外しても本文が通じるように書く。質問形と、説明のない専門用語も避ける。（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-structure/ ）
11. **キーワードは見出しの頭に置く。** 見出しは短く、具体的に書く。リストでも、読者は最初の数語に最も注意を払う。（出典: https://www.nngroup.com/articles/headings-pickup-lines/ ）
12. **ページタイトルはサイト内で重複させない。** 操作するページのタイトルは動作で始める。（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-titles/ ）
13. **要約の文言を本文の第1段落で繰り返さない。**（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/summaries/ ）
14. **文は短くする。** GOV.UK の基準は「25語を超える文は分割を試みる」「1段落は5文まで」。NN/g の基準は「1文 15〜20 語まで」「1〜2文だけの段落でもよい」。（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/ 、 https://www.nngroup.com/articles/plain-language-experts/ ）
15. **やさしい言葉は専門家にも有効。** 法律の専門家を対象にした研究では 80% が平易な文を好み、内容が複雑なほどその傾向は強まった。（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/ ）
16. **動作する人を明示して書く（能動態）。** 読者と、読者がすべき行動に焦点が当たる。（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/ ）
17. **手順には番号を付ける。** 各手順は完結した文で書く。箇条書きには前置きの一文を付け、1項目に1つの考えだけを入れる。（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/style-guides/a-to-z-style-guide/ ）
18. **書く前に利用者のニーズを特定し、その達成に必要なことだけを載せる。**（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/meet-user-needs/ ）
19. **脚注は使わない。**（出典: https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-structure/ ）
20. **見た目の数値で確認できたのは2点だけ。** 行の長さ「約50〜75文字」（英文。根拠の研究は引かれていない。出典: https://www.nngroup.com/articles/chunking/ ）と、行が長いほど行間を広く取る必要があること（出典: https://www.nngroup.com/articles/golden-ratio-ui-design/ ）。本文の最小の文字の大きさと行間の倍率は未確認。

## 日本語の文書に当てはめるときの注意

- **語数の基準（25語、15〜20語、111語、1,000語）は英語の単語数。** 日本語の文字数への換算は、どちらの出典にも無い（未確認）。日本語の上限は、プロジェクトが決めた値として `voice.md` の「一文の長さの目安」に書き、出典の値ではないと分かるようにする
- **行の長さ「50〜75文字」は英文の文字数。** 全角文字の1行の適正幅は未確認
- **F 字の視線は左から右へ読む英語での観察。** 日本語の横書きでも同じかは未確認。ただし、要点・見出し・リストの頭に情報量の多い語を置く原則は言語に関係なく使える
- **能動態は、日本語では「動作する人を明示して書く」と読み替える。** 「〜される」を機械的に禁止する意味ではない
- **79%・20〜28% は 1997年・2008年の英語圏の調査。** 方向性を示す根拠として使う

## 書くときのチェック項目

- [ ] ページ冒頭の2段落以内に、結論（読者が知るべきこと・すべきこと）があるか
- [ ] 見出しが内容を表しているか（「はじめに」「概要」「その他」だけの見出しは無いか）
- [ ] 見出しの最初の数語に、その節のキーワードがあるか
- [ ] 見出しが質問形になっていないか
- [ ] 見出しの階層を飛ばしていないか
- [ ] 1段落に考えが1つだけか。段落が5文を超えていないか
- [ ] 3つ以上の並列項目を箇条書きにしたか。箇条書きに前置きの一文があるか
- [ ] 順番のある操作を番号付きの手順にしたか
- [ ] 強調（太字）が要所だけになっているか
- [ ] 長い文書に目次・冒頭の要約・節へのリンクがあるか
- [ ] 読者の目的の達成に関係しない内容を削ったか
- [ ] 宣伝調・誇張表現が無いか

## 機械で検査できそうなこと

- 見出し階層の飛び（**実装済み**: `check-docs` の `headingSkip`）
- 1文の長さ・1段落の文数（上限はプロジェクトが決める）
- 中身の分からない見出し（はじめに・概要・その他）、質問形の見出し
- 強調の比率（太字の文字数が本文の 30% を超える）
- 本文が長いのに目次や冒頭の要約が無い文書
- 脚注の記法 `[^…]`
