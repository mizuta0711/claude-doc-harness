## 要点

1. **画像には、画像と同じ役割を果たすテキストを付ける。** 1.1.1 は「全ての非テキストコンテンツには、同等の目的を果たすテキストによる代替が提供されている」と定めている。ガイドブックは、画像の代わりにその文字を置いても違和感がない内容を求めている（出典: https://waic.jp/translations/WCAG22/ ・ガイドブック p.26 / 1.1.1）
2. **装飾だけの画像は `alt=""` にする。`alt` 属性そのものは省かない。** `alt` を省くと、スクリーンリーダーによってはファイル名を読み上げる（出典: https://www.w3.org/WAI/tutorials/images/decorative/ / 1.1.1）
3. **図表には要約を書く。** すぐそばの本文に要約があるなら、何の図表かを示したうえで `alt=""` にしてよい。リンクになっている画像はリンク先を書く。文字を画像にしたものは、画像中と同じ文字を書く（出典: ガイドブック p.26 / 1.1.1）
4. **代替テキストは 80 字を目安にする。** ガイドブックの目安で、仕様や規格に字数の制限は無い。文字が多い図は本文に書き起こせないか検討する（出典: ガイドブック p.26・p.50 / 1.1.1）
5. **複雑な図は「短い説明」と「長い説明」の2段にする。** 長い説明は、図の隣のリンク先に置くか `<figcaption>` に入れる（出典: https://www.w3.org/WAI/tutorials/images/complex/ / 1.1.1）。スクリーンショットだけを扱った記述は、どの出典でも未確認
6. **文字と背景のコントラスト比は 4.5:1 以上。大きな文字は 3:1 以上でよい。** WCAG の「大きな文字」は 18pt 以上、または 14pt 以上の太字で、CJK フォントはこれと同等のサイズとされる。ガイドブックは大きな文字の境目を「太字でない 22pt（29px）・太字 18pt（24px）」と書いており、WCAG の数値と一致しない。どちらを採るかはプロジェクトが決める（出典: https://www.w3.org/TR/WCAG22/ ・ガイドブック p.30 / 1.4.3）
7. **UI 部品の見た目と、図の中で意味を持つ部分は、隣の色と 3:1 以上の差をつける**（出典: https://www.w3.org/TR/WCAG22/ / 1.4.11）
8. **色だけで情報を伝えない。** 「赤字だけ」も、位置や形の違いだけも不可。必須項目なら「必須」のように文字の手がかりを添える（出典: https://www.w3.org/TR/WCAG22/ ・ガイドブック p.28 / 1.4.1・1.3.1・1.3.3）
9. **操作の説明を形・色・大きさ・位置・音だけに頼らない。** 「丸いボタン」「右のボタン」は悪い例。良い例は「右下の『次へ』と書かれた緑の矢印アイコン」のように、ラベルの文字も併記したもの（出典: https://www.w3.org/WAI/WCAG22/Understanding/sensory-characteristics.html / 1.3.3）
10. **見出しは内容を表す言葉にする。** 見出しを空にしない。強調や文字を大きくする目的で見出し要素を使わない（出典: https://www.w3.org/TR/WCAG22/ ・ガイドブック p.29 / 2.4.6・1.3.1）
11. **見出しレベルの飛ばしは、WCAG の達成基準では禁止されていない。** G141 は「h1 の次は h2、h2 の次は h2 か h3」と正しく入れ子にすべき（should）としているが、推奨である。ガイドブックも推奨として書いている（出典: https://www.w3.org/WAI/WCAG22/Techniques/general/G141 ・ガイドブック p.29 / 1.3.1）
12. **リンクの文言だけ、または文言と前後の文脈で、行き先が分かるようにする。** リンク先が PDF なのか、別ウィンドウで開くのかも事前に分かるようにする。同じ文言のリンクが並ぶと、スクリーンリーダーのリンク一覧で区別できない（出典: https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html ・ガイドブック p.32 / 2.4.4）
13. **`<html lang="ja">` でページの言語を指定する。** 言語の指定漏れは機械で見つかるが、どの言語が正しいかは人が確かめる（出典: https://www.w3.org/WAI/WCAG22/Techniques/html/H57 ・ガイドブック p.12 / 3.1.1）
14. **ブラウザの機能だけで文字を 200% まで拡大できるようにする。** 文字サイズを固定しない、`user-scalable=no` を使わない、拡大しても文字が重なったり見切れたりしない（出典: https://www.w3.org/TR/WCAG22/ ・ガイドブック p.30 / 1.4.4）
15. **幅 320 CSS px で横スクロールが要らないようにする。** データ表・図・地図は例外だが、表の個々のセルは例外にならない（出典: https://www.w3.org/WAI/WCAG22/Understanding/reflow.html / 1.4.10）
16. **利用者が文字の間隔を広げても、内容や機能が失われないようにする。** 対象の値は、行の高さ 1.5 倍、段落の後ろの間隔 2 倍、文字間隔 0.12 倍、単語間隔 0.16 倍（文字サイズ比）（出典: https://www.w3.org/TR/WCAG22/ / 1.4.12）
17. **表の見出しセルは `<th>`、データは `<td>` で書く。** タブや `<pre>` で列をそろえるやり方は見た目だけの表現として否定されている（出典: https://www.w3.org/WAI/WCAG22/Techniques/html/H51 / 1.3.1）
18. **1行の長さ。** WCAG 1.4.8（AAA）は「幅は 80 字以内（CJK は 40 字以内）」と定めている。ガイドブックに行の長さを扱った記述は未確認（出典: https://www.w3.org/TR/WCAG22/ / 1.4.8）
19. **国内の目標は AA。** ガイドブックは「原則 AA に適合させることを目標」としている。政府調達の標準は JIS X 8341-3:2016 の AA 準拠。AAA 準拠を目指すことは推奨していない（出典: ガイドブック p.19・p.38 / 適合レベル）
20. **JIS X 8341-3:2016 は WCAG 2.0 と同じ内容の一致規格**（出典: ガイドブック p.15）
21. **事業者にとっての位置づけ。** 2024-04-01 施行の改正障害者差別解消法で、事業者による合理的配慮が義務になった。ウェブアクセシビリティはその環境整備として努力義務とされている（出典: ガイドブック p.5）

## 書くときのチェック項目

- [ ] 情報を持つ画像すべてに、画像の代わりに置いて通じる代替テキストがあるか（80 字を目安）
- [ ] 装飾だけの画像を `alt=""` にしたか。`alt` を書き忘れた画像は無いか
- [ ] 図表の要点が本文か `<figcaption>` に書いてあるか
- [ ] 画像リンクの代替テキストがリンク先を表しているか
- [ ] 色の違いで区別しているところすべてに、文字やラベルの手がかりを併記したか
- [ ] 手順の文に「右の」「丸い」「緑の」だけで対象を指す箇所が無いか。ボタン名を書いたか
- [ ] 見出しが内容を表しているか。強調の目的で見出しを使っていないか
- [ ] 見出しが h1→h2→h3 の順に入れ子になっているか（WCAG の不適合ではないが推奨）
- [ ] リンクの文言だけで行き先が分かるか。PDF や別ウィンドウで開くリンクにその旨を書いたか
- [ ] 同じページに、同じ文言で行き先の違うリンクが無いか
- [ ] 表に `<th>` があるか。列をタブや空白でそろえていないか
- [ ] 配色を決めるとき、文字は 4.5:1（大きな文字は 3:1）、UI 部品と図の要素は 3:1 を満たしたか
- [ ] CSS で文字サイズを固定していないか。`user-scalable=no` が無いか
