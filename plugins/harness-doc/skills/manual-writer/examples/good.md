# 良い例: ローカルの開発サーバーを起動する

<!-- doc-type: howto -->
<!-- この文書は manual-writer の「良い例」。架空のプロジェクト my-app を題材にしている -->

## この文書でできること

my-app のリポジトリを clone した直後の開発者が、ローカルで開発サーバーを起動し、
ブラウザーでトップページが表示されるところまで到達できる。所要5分、全3手順。

読者: my-app を初めて触る開発者（プロファイル: developer）。Node.js と git は使える前提。

## 前提条件

- Node.js 22 以上がインストールされている（確認: `node --version` が `v22.` 以上を返す）
- リポジトリを clone 済みで、カレントディレクトリがリポジトリのルートである
- ポート 3000 を他のプロセスが使っていない

## 手順

### 1. 依存パッケージを入れる

```bash
npm ci
```

期待される出力（末尾）:

```text
added 412 packages in 18s
```

うまくいかない場合: `npm ERR! code EUSAGE` が出たら `package-lock.json` と `package.json` が
食い違っている。`git status` で `package-lock.json` を変更していないか確認する。

### 2. 環境変数ファイルを作る

```bash
cp .env.example .env
```

期待される状態: リポジトリのルートに `.env` ができる。中身は編集しなくてよい
（既定値でローカルの SQLite を使う。確認した場所: `.env.example` の `DATABASE_URL`）。

### 3. 開発サーバーを起動する

```bash
npm run dev
```

期待される出力:

```text
  ▲ Next.js 16.0.0
  - Local:        http://localhost:3000

 ✓ Ready in 1.8s
```

`Ready` が出るまで待つ（10秒以内）。

## 確認

ブラウザーで `http://localhost:3000` を開き、ページの見出しに「my-app」と表示されれば成功。

## うまくいかない場合

| 症状 | 原因 | 対処 |
|---|---|---|
| `Error: listen EADDRINUSE: address already in use :::3000` | ポート 3000 を別プロセスが使っている | `npm run dev -- -p 3001` で別ポートで起動し、`http://localhost:3001` を開く |
| ページが真っ白で、ターミナルに `PrismaClientInitializationError` | `.env` が無い | 手順2に戻る |

## なぜ良いか（例の解説。実際の文書には書かない）

- **冒頭でゴール・読者・所要・手順数が分かる。** 読む前に「自分向けか」「どれくらいかかるか」を判断できる
- **前提条件に確認方法が付いている。** 「Node.js 22 以上」だけでなく `node --version` の結果まで
- **手順ごとに期待される出力がある。** 成功したかをその場で判断できる
- **失敗しやすい箇所の直後に「うまくいかない場合」がある。** 末尾の表まで読みに行かなくてよい
- **「確認した場所」がある。** `.env.example` の `DATABASE_URL` を読んで書いたことが分かる
- **曖昧語が無い。** 「`しばらく待つ`」ではなく「`Ready` が出るまで（10秒以内）」
