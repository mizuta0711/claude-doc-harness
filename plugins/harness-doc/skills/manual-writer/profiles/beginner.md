# 読者プロファイル: beginner（初めて使う人）

## 読者像

- このアプリ・ツールを**初めて使う**。業務知識はあるかもしれないが、この製品の用語・画面構成は知らない
- **画面を見ながら読む**。文書と画面を行き来する。読んでいる途中で画面が変わると迷う
- コマンドラインに慣れていない。「ターミナルを開く」から説明が要ることがある
- 読む状況: 落ち着いているが、**先が見えないと不安になる**。全体で何手順あるか知りたい

## この読者が最もつまずく点

1. **画面名・ボタン名が文書と違う。** 「設定画面」と書いてあるが画面には「環境設定」とある、で止まる
2. **自分がどこにいるか分からない。** 手順3の前にダイアログが出て、文書のどの状態なのか分からない
3. **専門用語が説明なしに出る。** 「リポジトリ」「トークン」「エンドポイント」で読む気を失う
4. **成功したか判断できない。** 操作したが何も起きないように見え、やり直して二重登録する
5. **前提が書かれていない。** 手順どおりやったのに権限エラーで止まり、自分のせいだと思う

## この読者向けの書き方の調整

- **目次を「やりたいこと」で作る。** 「ログインする」「レポートを出す」。機能名で作らない
- **画面名・ボタン名は UI の表記と完全に一致させ、太字にする。** 「**環境設定**」「**保存**」
- **画面の状態を手順ごとに書く。** 「〜を押すと、〇〇ダイアログが開く」。画像が撮れるなら付ける
- **専門用語は初出で1文の説明を付ける。** 説明が2文以上要る語は、使わずに言い換える
- **手順の総数を先に書く。** 「全5手順。所要10分」
- **やってはいけないことを、その手順の直前に書く。** 後からでは遅い
- 失敗したら戻れることを書く。「**キャンセル**を押せば何も保存されない」

## レビュー時の観点

`doc-reviewer` はこの読者になりきって、次を点検する。

- 画面にある文字列と文書の文字列が一致しているか（一致を確認できない場合は「未確認」の明記があるか）
- 各手順の直後に「何が起きるか」が書いてあるか
- 説明なしの専門用語が無いか
- 前提条件（アカウント・権限・インストール）を読む前に揃えられるか
- 途中で失敗したとき、どこまで戻ればよいか分かるか
