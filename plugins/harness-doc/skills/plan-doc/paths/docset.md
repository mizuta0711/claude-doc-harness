# plan-doc の経路: 文書群の見直し

「文書全体を見直して」「どれから直せばいいか」「要らない文書はどれか」「入口から辿れない文書はあるか」のように、1本ではなく文書群を見たい依頼は、この手順で進める。
`${CLAUDE_SKILL_DIR}` は plan-doc のフォルダー（絶対パスに置き換えて書く）。

**この経路は文書を書き換えない。** 結果を見せ、直す順を決めて終える。**受付の 1-3（前提と経緯を読む）・1-4（基準点の記録）と Step 2（規模の判定）は飛ばす。**
`--mark` で基準点を作ると、次の作業が残った基準点と比べてしまう（文書を書き換えないので、作る理由が無い）。

**確認の回数は1回**（直す順）。

## 1. 結果を集める

```bash
node "${CLAUDE_SKILL_DIR}/../../scripts/docset.mjs"
```

文書群（ブリーフ）ごとに、次が出る。範囲を絞るなら `--brief <名前>`。1本が入口から辿れるかだけなら `--reach <文書のパス>`。**出力はファイルに残さない**（文書群の地図・本数・一覧は、次に文書を足したときに古くなる）。

| 項目 | 中身 | 読み方 |
|---|---|---|
| 1. 文書の一覧 | 文書ごとの `doc-type`・最初の見出し・出ていくリンクと入ってくるリンクの数 | 入ってくるリンクが 0 の文書は、入口が決まっていれば 2 に出る |
| 2. 入口から辿れない文書（孤立の候補） | 入口のファイルからリンクを辿って届かない文書。届かなかった理由が付く | **候補**。入口の更新を忘れただけか、要らない文書かは人が決める。入口が決まっていない文書群には出ない |
| 3. 重複の候補 | 同じ見出しの数と、同じコードの行が3行以上続く箇所の数が多い文書の組（上位10組） | **候補**。同じ内容か・矛盾していないかは、2本を読んで決める。**比べるのは同じ文書群の文書だけ**（README と手順書の重複は見ない。README のように文書群 `default` の文書は、ほかの文書群と比べないので、疑わしければ自分で `Grep` する）。入口のファイルと `doc-type: landing` の文書・各文書の題名（最初の見出し）は比べない |
| 4. 種類の偏り | `doc-type` ごとの本数と、マーカーの無い文書の本数 | 数だけ。種類が欠けているかは、読者の目的で決まる |
| 5. リンク切れ | 文書群全体の、行き先やアンカーが無いリンク | そのまま直す対象 |
| 6. 廃止の候補 | 2 と、3 の上位の組の両方に出る文書（重複の相手の名前が付く） | 候補。消すか統合するかは人が決める |

入口が決まっていない文書群があれば、孤立は見ていないと伝え、入口を決めるなら `/harness-doc:setup-project` の「導入済みのプロジェクトに足す」を勧める（1行。問いにしない）。

## 2. 直す順を案にする

直すものを、`manual-writer` の `references/structure.md` の「既存の文書群は1か所ずつ直す」に従って**1本ずつの順**に並べる。並べ方:

1. リンク切れ（読者がすぐ困る。入口から辿れない文書の入口への登録もここ）
2. 廃止の候補（消す・統合するかで、直す対象が減る）
3. 重複の候補（同じ内容を1か所に寄せる）
4. 種類の偏りで気づいたこと（足りない種類は、依頼者の目的を聞いてから）

各行に、1本の名前・何を直すか・根拠（`docset.mjs` の出力のどの行か）を書く。**機械が出したのは候補なので、「要らない」「矛盾している」と断定しない。**

## 3. 依頼者に1回聞く

結果の表（1〜6）と直す順の案を、**問いの直前の出力に全部書いてから**聞く。選択肢:

- 「この順で直す（推奨）」: 順を完了報告に書き、1本目を改訂として受け直す
- 「残作業に写す」: 一覧を完了報告に全部書く
- 「順を変える（どこを）」

**どちらを選んでも、順の一覧をプロジェクトの残作業の置き場所（課題管理・TODO のファイル）へ写すよう、1行で勧める。** 次のセッションでは、チャットの順は失われる。ハーネスは順をファイルに残さない（プロジェクトの残作業の置き場所が正）。

## 4. 終え方

- 「この順で直す」: 1本目を、plan-doc の受付（Step 1）から**新しい依頼として**受け直す。確認の回数は数え直す。規模はその1本で判定する。2本目以降は、依頼者が頼むたびに受ける
- 「残作業に写す」: 完了報告に一覧を全部書いて終える
- 完了報告に書くもの: 見た範囲（文書群の名前と本数）・結果の要約・直す順（または一覧）・入口が決まっていない文書群・「依頼者が次にやること」（順を残作業の置き場所に写す）
- 消す・統合すると決まったら、入口とほかの文書からのリンクを外すところまでを**1つの改訂**にする（外し忘れは、完了処理の検査が「外から入ってくるリンクの切れ」で止める）。消すか、残して「この文書は〇〇に移した」と書くかは、公開済みかどうかで変わるので、プロジェクトが決める
