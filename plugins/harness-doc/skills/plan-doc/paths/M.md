# plan-doc の経路: M（新規作成・改訂・誤りの修正）

規模 M（新規作成・改訂・誤りの修正）と承認されたら、この手順で**改訂設計書**を作り、承認を取ってから `manual-writer` に渡す。
規模 L は `show.mjs path L`（この経路の 1 を使い、Stage 1 と試作を足す）、テイスト変更は `show.mjs path tone`。
`${CLAUDE_SKILL_DIR}` は plan-doc のフォルダー（絶対パスに置き換えて書く）。

**確認の回数は M で3回**（規模と前提 → この設計書 → 完了前の確認）。`manual-writer` は改訂設計書があれば Step 1 の問いと Step 3 の承認を省くので、回数は増えない。

## 1. 改訂設計書を作る

1. 雛形を出力し、`docs-style/plans/YYYYMMDD_<名前>.md`（config の `plansDir`。名前は英数字とハイフン）に `Write` で書く

   ```bash
   node "${CLAUDE_SKILL_DIR}/../../presets/show.mjs" plan-template
   ```

2. 埋める

   | 節 | 埋め方 |
   |---|---|
   | 表（状態・対象の文書・性質と規模・入口への登録・承認） | 状態は「作業中」。対象の文書は、直す・作る文書を全部（バッククォートで囲む。コミット時の検査がこの一覧を読む）。**新規作成なら「入口への登録」の行**に、どの入口のファイルの、どこに足すかを書く（`brief.mjs show` の「入口」。決まっていなければ「入口なし（ブリーフに入口が無い）」）。**入口のファイルは「対象の文書」にも入れ、`--mark --add` で基準点に足す**（直した文書なので、改訂の記録が要る。読者向けの改訂履歴が「あり」なら1行も要る。例外は作らない。読者にとっても目次の変化は変化） |
   | 症状 | 受付で読み取った症状（改訂・誤りの修正）。新規作成なら「新規」 |
   | 受け入れ基準 | 「文書の基準」はブリーフの文書ごとの決め事から番号と要点を並べる（無ければ案を作る）。「今回の改訂の基準」はこの改訂だけの基準。どちらもチェックボックス |
   | 改訂方針 | 変えること・変えないこと・分量の上限・見積もり（本数・読者役は2回まで）・**これまでの経緯**（受付で `history.mjs show` から読んだ改訂意図と見送ったこと。反する直し方をするなら、そう書く） |
   | 目次案 | 新規作成なら全体の目次。改訂なら変える節と、増やす・消す見出し。先に `show.mjs reference structure` と `reference web` を出力して読む。**節ごとに図・画面を付けるか**（`voice.md` の「図の描き方」の方式か「なし」。既定は「なし」で、付けるなら理由）も書く |
   | 試作 | 「対象外（規模 M）」と1行書く |
   | タスク一覧 | 雛形のまま（`manual-writer` の手順が並んでいる）。足すタスクがあれば足す |

3. 文書の種類（手順書・リファレンス・仕様書）とゴールがブリーフに無ければ、案を作って設計書の受け入れ基準の上に書く（承認の後、ブリーフに書く）

## 2. 承認を取る（2回目）

改訂設計書の**受け入れ基準と目次案を、問いの直前の出力に全部書いてから**、1回で承認をもらう（設計書のパスだけを示して「見てください」としない。依頼者からは見えないことがある）。

- 選択肢は「この設計書で進める（推奨）」「直す（どこを）」
- ブリーフの `missing` が挙げた欠けている項目・仮定の項目があれば、同じ問いで聞く
- 新規作成の文書の見出しの語が、既存のサイトと `check-docs` の必須見出し（手順書なら「できること」「前提条件」「手順」「確認」「うまくいかない場合」）で違うなら、どちらに寄せるかも同じ問いで聞く（`manual-writer` Step 3 の文書種別マーカーの段。ここで聞かないと、4回目の確認になる）
- 承認されたら、表の「承認」に日付と承認者を書く。受け入れ基準・ゴール・文書の種類は、ブリーフの文書ごとの決め事に `"by":"依頼者"` で書く（`apply.mjs --brief`）

## 3. manual-writer に渡す

`/harness-doc:manual-writer` を、次を添えて呼ぶ。

- 改訂設計書のパス（「改訂設計書: docs-style/plans/20261005_phone.md（承認済み）」）
- 承認した規模と前提

`manual-writer` は設計書を読み、Step 2 から書き始める。タスクを終えるたびに設計書のチェックを付け、最後の Step で `show.mjs path finish`（完了前の確認と完了処理）を読んで終える。**plan-doc に戻ってこない。**
