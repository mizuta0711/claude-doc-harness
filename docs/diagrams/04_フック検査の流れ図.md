# フック検査の流れ図 — 何を読み、何を見るか

| 項目 | 内容 |
|---|---|
| 対応ハーネス版 | harness-doc 0.12.0 |

harness-doc のフックが何を読み、何を見るかを示す図。`check-docs`（書き込みのたび）・`commit-check`（コミットの前）・`reviewer-guard`（読者役が読むとき）の3つがある。

## 書き込みのたびの検査（check-docs）

`check-docs` フックが、1回の書き込みで対象を判定し、検査し、結果を返すまでの流れ。

**ポイント**:

- **素通りの条件が先に並ぶ。** 設定が無い・対象外のファイル・抑止マーカーがある、のどれかなら何もしない
- **Markdown と HTML で、本文の取り出し方だけが違う。** 取り出した後の検査（曖昧語・用語集・文末・リンク・見出し）は共通
- **違反は Claude に返る。** 終了コード 2 で、指摘が Claude に渡り、Claude が直す
- **止めるのは、直前のコミットより増えた指摘だけ**（0.12.0）。前からある指摘は件数だけを伝える。リンク切れと lint は比べずに毎回止める

### 図

```mermaid
flowchart TD
    W["Claude が Write / Edit で書いた"]
    C1{"設定ファイルがあるか<br/>.claude/doc-harness.config.json"}
    C2{"拡張子が .md / .html か<br/>include に当たり exclude に当たらないか"}
    C3{"冒頭に skip マーカーがあるか"}
    PASS(["何もしない<br/>終了コード 0"])

    FMT{"形式"}
    MD["Markdown<br/>コードブロック・インラインコードを外す"]
    HTML["HTML<br/>タグ・属性・script・style・pre・code・コメントを外す<br/>文字実体参照を戻す"]

    subgraph CHECKS["共通の検査"]
        direction TB
        K1["曖昧語<br/>banned-words.txt"]
        K2["用語集<br/>glossary.md と glossaryFiles"]
        K3["文末の混在<br/>voice.endings を設定したときだけ"]
        K4["リンク切れ・アンカー切れ<br/>Markdown はリンク・HTML は href と src<br/>アンカーは出ていくリンクだけ"]
        K5["必須見出し<br/>doc-type マーカーがあるときだけ"]
        K6["言語指定・markdownlint・textlint<br/>Markdown だけ"]
    end

    R{"指摘があるか"}
    OK(["終了コード 0"])
    HEAD{"直前のコミットの版を読めるか<br/>git show HEAD:./ファイル名"}
    DIFF{"増えた指摘があるか<br/>種類と文言の組で数える<br/>リンク切れ・lint は常に増えた側"}
    KEPT(["終了コード 0<br/>前からある件数を Claude に伝える"])
    NG(["終了コード 2<br/>増えた指摘を Claude に返す → Claude が直す"])
    NGALL(["終了コード 2<br/>全部の指摘を返す"])

    W --> C1
    C1 -- ない --> PASS
    C1 -- ある --> C2
    C2 -- 当たらない --> PASS
    C2 -- 当たる --> C3
    C3 -- ある --> PASS
    C3 -- ない --> FMT
    FMT -- .md --> MD --> CHECKS
    FMT -- .html --> HTML --> CHECKS
    CHECKS --> R
    R -- ない --> OK
    R -- ある --> HEAD
    HEAD -- 読めない --> NGALL
    HEAD -- 読める --> DIFF
    DIFF -- ない --> KEPT
    DIFF -- ある --> NG
```

### 読み方

- 行に `<!-- check-docs: ignore 理由 -->` があれば、その行の曖昧語・用語集・リンク切れは見ない
- 設定ファイル・用語集・曖昧語リストは**書き込みのたびに読み直す**。決まりを変えると次の書き込みから効く
- 書き込みそのものは止められない（ツールが実行された後に走るため）。差し戻して直させる方式である

検査項目の細かい規則は [check-docs 仕様](../reference/check-docs仕様.md) にある。

## コミット時の検査（0.10.0）

`commit-check` フックが、Claude の `git commit` の前に、文書の改訂の記録があるかを確かめる流れ。
スキルを通らなかった作業（続けての依頼で `plan-doc` を使わなかったとき）も、ここで止まる。

```mermaid
flowchart TD
    B["Claude が Bash / PowerShell でコマンドを実行しようとした"]
    G{"コマンドに git commit があるか<br/>引用符・ヒアドキュメントの中は数えない"}
    P{"対象のリポジトリに設定ファイルがあり<br/>completeCheck が off でないか<br/>cd・git -C・cwd から決める"}
    PASS(["何もしない"])
    IDX["コミットの中身を一時の index で再現する<br/>同じコマンドの git add・-- パス・-a を当てる"]
    U{"再現できたか"}
    DENY1(["止める<br/>git add と git commit を分ける"])
    PROTO{"試作のファイル<br/>（名前に .proto-数字）を含むか"}
    DENY0(["止める<br/>試作のファイルを消して外す"])
    DOCS{"文書（include）を含むか"}
    BR{"ブリーフがあるか"}
    WARN1(["警告だけ<br/>setup-project の「足す」を案内"])
    CHK["文書ごとに確かめる<br/>改訂記録の節・改訂意図・読者向けの1行<br/>M/L の改訂設計書<br/>（問い合わせの印は警告だけ）"]
    R{"足りないものがあるか"}
    PLAN{"同じコミットの改訂設計書が<br/>作業中か"}
    SKIP{"文言に doc-record: skip があるか"}
    FORM{"理由が「改訂の記録なしで<br/>コミットする: 理由」の形か"}
    OK(["通す"])
    WARN2(["警告だけ"])
    ASK(["依頼者に承認を求める"])
    DENY2(["止める<br/>記録を足してからコミットし直す"])

    B --> G
    G -- ない --> PASS
    G -- ある --> P
    P -- 当たらない --> PASS
    P -- 当たる --> IDX --> U
    U -- できない --> DENY1
    U -- できた --> PROTO
    PROTO -- 含む --> DENY0
    PROTO -- 含まない --> DOCS
    DOCS -- 含まない --> OK
    DOCS -- 含む --> BR
    BR -- 無い --> WARN1
    BR -- ある --> CHK --> R
    R -- ない --> OK
    R -- ある --> PLAN
    PLAN -- 作業中 --> WARN2
    PLAN -- それ以外 --> SKIP
    SKIP -- ある --> FORM
    FORM -- その形 --> ASK
    FORM -- 違う形 --> DENY2
    SKIP -- ない --> DENY2
```

- 判定は `scripts/complete-doc.mjs` の `--staged` と同じ。`--amend` は1つ前の版と比べる
- **問い合わせの印（`<!-- 問い合わせ: -->`）は、コミット時は警告だけ**。印は改訂設計書の「問い合わせ」で管理していて、依頼者の回答を待つあいだ残るのが正しい状態のため。完了報告の前の検査（`complete-doc.mjs`）では NG（`--allow-queries` で警告）
- 試作のファイル（`<名前>.proto-1.<拡張子>`）がコミットに入っていたら、文書の記録の有無にかかわらず止める
- 検査が20秒で終わらなければ止め、文書を分けてコミットするよう返す
- 止めたときの表示の1行目は、理由によらず「❌ 改訂の記録が無い文書を含むコミット」。理由は2行目から後に書く
- 人が手でしたコミットは止まらない（Claude のコマンドだけを見るフック）
- `doc-record: skip（改訂の記録なしでコミットする: <理由>）` は、harness-doc の工程を通さない正当な変更のための印。止める代わりに依頼者の承認を求める（`ask`）。承認の画面にはフックの理由が出ず、コマンドの本文だけが出るので、何を承認するのかが本文から読めるよう、理由の書き方を決めている。この形でない `doc-record: skip` は止める
- 対話の許可を省くモード（bypassPermissions）でも、`ask` は承認の画面を出す（実地検証で確かめた）。非対話で承認を求められないときは、コミットは止まる
- config の `completeCheck` が `"warn"` なら、止める代わりに警告だけを出す。`"off"` なら何もしない
- 「作業中」のまま7日を超えた改訂設計書があれば、警告に出す
- git の別名（alias）・`git revert`・`cherry-pick`・`merge` で作るコミットは見ていない

## 読者役の読む範囲（0.10.0）

`reviewer-guard` フックは、読者役（`doc-reviewer`）が内部の改訂記録（`docs-style/history/`）と改訂設計書（`docs-style/plans/`）を読むのを止める。
`Read` はその中のファイルを、`Grep` はそれを含む範囲（プロジェクトのルートのような、記録を含むフォルダー）の検索を止める。メインのエージェントとほかのエージェントは止めない。
