# ハーネスを自分のプロジェクトに導入する

<!-- doc-type: howto -->

## この文書でできること

Claude Code を使っているプロジェクトに文書ハーネスを導入し、「〇〇の手順書を書いて」と頼むだけで、
決まった手順で書かれ、読者の立場での点検と自動の検査を通った文書が出てくる状態にできる。
**利用者はプラグインを操作するコマンドを打たない**（Claude Code の起動と終了を除く）。すべて Claude Code に日本語で頼む。所要5分、全3手順。

読者: Claude Code を日常的に使っている人。プラグインの仕組みを知らなくてよい。

対応ハーネス版: harness-doc 0.13.0（入っている版の確かめ方は「プラグインを更新する」）。

この文書で使う言葉:

| 言葉 | 意味 |
|---|---|
| 文書ハーネス | 文書を決まった手順で書かせるための追加機能一式。Claude Code に後から足す |
| プラグイン | Claude Code に後から足す追加機能の単位。文書ハーネスは `harness-doc` という名前のプラグインとして入る |
| マーケットプレイス | プラグインの配布元。1回登録すると、そこからプラグインを入れられる |
| スキル | プラグインが Claude Code に足す「決まった作業手順」。日本語で頼むと、Claude が合うスキルを選んで使う |
| フック | 文書が保存されるたびに自動で動く検査。曖昧な語や書式の誤りを見つけると、Claude に直させる。Claude がコミット（git に変更を記録すること）するときにも、改訂の記録があるかを確かめ、無ければコミットを止める |
| 検査対象 | フックが検査する文書。導入のときに場所を決める |
| `CLAUDE.md` | プロジェクトのフォルダーに置く、Claude Code への指示書。Claude は毎回これを読んでから作業する |
| 文書群 | 同じ読者に向けた文書のまとまり（例: `docs/利用マニュアル/` の下の文書全部） |
| ブリーフ | 文書群ごとの読者と扱わないことを書いた決め事のファイル |

## 前提条件

- **Claude Code から `claude` コマンドを実行できる。** VS Code の拡張だけを使っていると、このコマンドが無いことがある。 Claude Code に「`claude --version` を実行して」と頼み、
  `2.1.283 (Claude Code)` のような版番号が返れば使える。返らない場合は、Claude Code に「Claude Code のターミナル版を入れて」と頼む。
  入れたら Claude Code を再起動し（手順「2. Claude Code を再起動する」と同じ操作）、もう一度 `claude --version` で確かめる。
  入れるところで失敗したら、エラーの文をそのまま貼って「このエラーを解決して」と頼む
- **Node.js が入っている。** フックが使う。Claude Code に「`node --version` を実行して」と頼み、
  `v` で始まる版番号が返れば入っている。返らない場合は、Claude Code に次のように頼むと入る（Windows の場合）

  ```text
  winget install --id OpenJS.NodeJS.LTS --exact を実行して Node.js を入れて
  ```

  Windows 以外では「Node.js の LTS 版（長く保守される安定版）を入れて」と頼む（Windows 以外での動作は未確認）。
  入れたら Claude Code を再起動する（手順「2. Claude Code を再起動する」と同じ操作）。動作を確認したのは v24 と v22。v22 より古い版が返ったら、上と同じ頼み方で LTS 版を入れ直す
- **プロジェクトを git で管理している（推奨）。** git で管理していないプロジェクトでも文書は書かせられる。ただし、改訂の記録を確かめる検査（完了処理の検査とコミットのときの検査）が働かず、書き直しを採用せずに「やり直す」を選んでも、作業前の中身に戻せない
- **インターネットにつながっている。** 手順1で GitHub からプラグインを取ってくる

## 手順

### 1. プラグインを入れる（このマシンで1回だけ）

どのプロジェクトで開いた Claude Code でもよい。次の文をそのまま貼って頼む。

```text
次の2つのコマンドを実行して、文書ハーネスのプラグインを入れて。
claude plugin marketplace add mizuta0711/claude-doc-harness
claude plugin install harness-doc@doc-harness --scope user
```

コマンドの実行の許可を求められたら、許可する（2回出ることがある）。ターミナル版の画面では `Do you want to proceed?` の下に `Yes`・`Yes, and don't ask again for …`・`No, and tell Claude what to do differently` が並ぶ（VS Code 拡張では表示が違うことがある）。`Yes` を選ぶ。
拒否してしまったら、同じ文をもう一度貼って頼む。既に済んだ方は別のメッセージになるだけで、害は無い。

期待される結果: Claude Code が2つを実行し、出力に次の2行が含まれる。

```text
✔ Successfully added marketplace: doc-harness (declared in user settings)
✔ Successfully installed plugin: harness-doc@doc-harness (scope: user)
```

1行目は、マーケットプレイスを既に登録済みなら別のメッセージになる。2行目が出ていれば先へ進んでよい。

このプラグインは、このマシンのすべてのプロジェクトに入る。ただし手順3を済ませたプロジェクトでしか動かないので、
他のプロジェクトの作業の邪魔にはならない。

うまくいかない場合: 2行目が出なかったら、エラーの文をそのまま貼って「このエラーを解決して」と頼む。
多い原因は、インターネットにつながっていない、または会社のネットワークで GitHub への接続が止められていることである。

### 2. Claude Code を再起動する

プラグインは再起動したときに読み込まれる。使っている画面に合わせて操作する。

| 使っている画面 | 操作 |
|---|---|
| VS Code の Claude Code 拡張 | 開いている VS Code のウィンドウをすべて閉じて、開き直す。導入したいプロジェクトのフォルダーを開き、Claude Code のパネルを開く |
| ターミナル | `/exit` と入力して終了し、導入したいプロジェクトのフォルダーで `claude` と入力して起動する |

期待される結果: 再起動後に「harness-doc のスキルは使える？」と聞くと、答えに `setup-project`（導入する）と
`plan-doc`（文書を書く・直す依頼の入口）と `manual-writer`（文書を書く。`plan-doc` から使う）が挙がる。答えの文と並び順は毎回変わるので、3つの名前がどこかに出ていればよい。

うまくいかない場合: 挙がらなければ、末尾の「うまくいかない場合」の表の「`setup-project` が見つからない」と「VS Code 拡張でだけスキルが見つからない」の行を見る。

### 3. プロジェクトに導入する（プロジェクトごとに1回だけ）

導入したいプロジェクトで開いた Claude Code に頼む。

```text
このプロジェクトに文書ハーネスを入れて
```

スキルの使用やコマンドの実行の許可を求められたら、許可する。

`setup-project` スキルが動き、次の4つを置く。

| 置くもの | 役割 |
|---|---|
| `CLAUDE.md` の「文書ルール（harness-doc）」の節 | Claude に、文書を書く前に決まった手順を踏ませる。`CLAUDE.md` が無ければ新しく作る |
| `docs-style/` フォルダー | 用語集・曖昧な語の一覧・使い方の1ページ。使いながら育てる |
| `.claude/doc-harness.config.json` | どの文書を検査するかの設定。**これが無いと、フックは何も検査しない** |
| `.claude/rules/doc-brief-*.md`（ブリーフ） | 文書群ごとの読者・扱わないこと。導入のときに案を確かめて決める。**一度決めれば、文書を書くたびに読者を聞かれない** |

途中で、次のことを聞かれる（選択肢の画面で答える）。

- 既存の文書があれば、検査する文書の場所と、今の文体・用語表を引き継ぐか。無ければ、文体と見た目を見本から選ぶ。迷ったら「（推奨）」の付いた選択肢を選ぶ。文体は後から「文書をもっとやさしい言葉に変えて」のように頼めば変えられる（[運用ガイド](運用ガイド.md)）
- 最後に、文書群の分け方と、文書群ごとの読者・扱わないことの案。分からなければ案のまま「それでよい」と答えてよい。後から「〇〇の読者を△△に変えたい」と頼めば変えられる

期待される結果: 完了報告の表が出て、「置いたもの」に上の表の最初の3つが並ぶ。4つ目のブリーフは「置いたもの」ではなく「文書群とブリーフ」の行に、文書群ごとの読者と一緒に出る。

**既にある `CLAUDE.md` は、内容を消さずに末尾へ節を1つ足すだけ。** それ以外の既にあるファイルには触らない。
2回目に頼むと、すべて「触らなかったもの」に並ぶ。
この手順は再起動しなくても有効になる。

**claude-dev-harness（開発用のハーネス）を使っていなければ、次の段落は飛ばしてよい。**
使っているプロジェクトでは、報告に「dev-harness 併用」と出る。`docs/設計書/`・`docs/features/`・
`docs/reviews/`・`docs/handoff/` は検査対象から自動で外れ、これまでどおり claude-dev-harness が扱う。
残りの `docs/` 配下（利用マニュアル・運用手順）と `README.md` が検査対象になる。

## 確認

Claude Code に次の文をそのまま頼む。ファイル名 `harness-check.md` は、既存のファイルとぶつからないように選んである。
`docs/` フォルダーが無ければ作られる。

```text
docs/harness-check.md に「必要に応じて再起動する。」の1行だけを、言い換えずにそのまま書いて。フックの指摘が出たら、その指摘をそのまま見せて
```

指摘に `曖昧語「必要に応じて」` という文字が含まれていれば成功。実際の指摘は次の形で出る。

```text
  L1    曖昧語「必要に応じて」: 条件と値を具体的に書く
```

指摘は Claude にも渡るので、Claude が続けてファイルを直すことがある。**これは失敗ではない。**
Claude が最初から言い換えて書き、指摘が一度も出ない場合は、「言い換えずに」と念を押して頼み直す。

確認が済んだら「docs/harness-check.md を消して」と頼む。この確認で `docs/` フォルダーが新しくできた場合は、
残しておいてよい。文書の置き場所になる。

## 次にやること

文書を頼む。**誰が読むか**と**読み終えたら何ができるべきか**を添えると、聞き返しが減る。

```text
ログインの手順書を、初めて使う人向けに書いて。読み終えたら自分でログインできるようにしたい
```

既にある文書を直すときも同じように頼む。

```text
docs/利用マニュアル/ログイン.md を、初めて使う人が迷わないように書き直して
```

途中で、読者や目次案の確認を求められる。答えると先に進み、最後に完了報告の表が出る。

**最初の1本を頼む前に（または頼みながら）、[入門ガイド](入門ガイド.md) を読む。** どこで何を聞かれるか、完了報告のどこを見るか、コミットが止まったときにどうするかが書いてある。

## プラグインを更新する

新しい版で何が変わったかは、[CHANGELOG](https://github.com/mizuta0711/claude-doc-harness/blob/master/CHANGELOG.md) にある。確かめずに更新を頼んでもよい（最新なら何も変わらない）。

どのプロジェクトで開いた Claude Code でもよいので、次の文をそのまま貼って頼む。

```text
次の2つのコマンドを実行して、文書ハーネスのプラグインを更新して。
claude plugin marketplace update doc-harness
claude plugin update harness-doc@doc-harness
```

期待される結果: 1つ目のコマンドの出力に `✔ Successfully updated marketplace: doc-harness` が出る。2つ目は、新しい版があれば次のような1行が出る（数字は前と後の版）。

```text
✔ Plugin "harness-doc" updated from 0.11.1 to 0.11.2 for scope user. Restart to apply changes.
```

既に最新なら次の1行が出る（括弧の中は今の版）。

```text
✔ harness-doc is already at the latest version (0.11.2).
```

終わったら Claude Code を再起動する（手順「2. Claude Code を再起動する」と同じ操作）。更新は再起動して初めて効く。
再起動の後、「`claude plugin list` を実行して」と頼むと、`harness-doc@doc-harness` の下の `Version:` の行に今の版が出る。上がっていれば成功。エラーが出たら、エラーの文をそのまま貼って「このエラーを解決して」と頼む。

**更新しても、プロジェクトに置いた `docs-style/`・ブリーフ・設定ファイルは書き換わらない。** 更新したら、使っている各プロジェクトで「このプロジェクトに文書ハーネスを入れて」ともう一度頼む。新しい版で `CLAUDE.md` の節や使い方の1ページが変わっていれば、置き換えるかを聞いてくる。足りないものが無ければ、そう報告されるだけで何も変わらない。
**取り外してから入れ直す必要は無い。** 取り外しは、プロジェクトの用語集や改訂の記録を消す操作である。

## うまくいかない場合

| 症状 | 原因 | 対処 |
|---|---|---|
| 手順2〜3で `setup-project` が見つからない | 再起動していない、または手順1が失敗している | 手順2をやり直す。直らなければ「`claude plugin list` を実行して」と頼み、`harness-doc` の行に `Status: ✔ enabled` があるか見る。無ければ手順1をやり直す |
| 手順1〜2を済ませたのに、VS Code 拡張でだけスキルが見つからない | Windows の VS Code 拡張の既知の不具合（[anthropics/claude-code#74912](https://github.com/anthropics/claude-code/issues/74912)） | ターミナル版で使う。VS Code のメニューの **ターミナル** → **新しいターミナル** を開き、`claude` と入力する |
| 手順3で、スキルを使う許可を拒否してしまった | 許可しないとスキルの中身が読めない | もう一度同じ文で頼み、今度は許可する |
| 手順3が途中で止まり、完了報告の表が出ない | 途中の問いに答えずに終わった、または通信が切れた | 質問の途中で止まったなら、同じ文でもう一度頼む。既にあるファイルは上書きされない。ファイルを置いた後で止まった（`docs-style/` ができている）なら、もう一度頼むと足りないものだけが足される。文体と検査する場所は決め直されないので、違っていれば「`〇〇` も検査対象に入れて」「文書をもっとやさしい言葉に変えて」のように頼む（[運用ガイド](運用ガイド.md)） |
| 確認で指摘が出ない | (1) 手順3が済んでいない (2) `docs/` の外に書かせた (3) Node.js が入っていない | (1) 手順3を頼む (2) `docs/` の下に書かせる (3) 前提条件の Node.js の入れ方に従う |
| 設計書を頼んだら「対象外」と言われる（claude-dev-harness を使っている場合） | 設計書は claude-dev-harness が扱う | 正常。設計書は「harness-core の update-docs で設計書を更新して」のように、claude-dev-harness のスキルを名指しして頼む |
| `docs/` 以外の文書も検査してほしい | 最初の設定で検査するのは `docs/` 配下と `README.md` だけ | 「`guides/` 配下も検査対象に入れて」のように頼む。Claude が設定ファイルに足す |

## 取り外し

**外す順番: 先に、使っていた各プロジェクトから外す。そのあとでマシンから外す。**
`CLAUDE.md` の節は、プラグインを外しても Claude への指示として残る。マシンから先に外すと、各プロジェクトに節が残ったままになる。

### 1. 各プロジェクトから外す

`docs-style/` には、使いながら育てた用語集・曖昧な語の一覧・`voice.md` と、改訂の記録（`docs-style/history/`）・改訂設計書（`docs-style/plans/`）が入っている。後で入れ直すつもりか、記録を残したいなら、先に退避を頼む。

```text
docs-style/ フォルダーを丸ごと、ホームフォルダーの Documents/harness-backup/ にコピーして
```

そのあと、外したいプロジェクトで頼む。

```text
このプロジェクトから文書ハーネスを外して。CLAUDE.md の「文書ルール（harness-doc）」の節、docs-style/、.claude/doc-harness.config.json、.claude/rules/doc-brief-*.md、.git/harness-doc/ を消して
```

ブリーフ（`.claude/rules/doc-brief-*.md`）は Claude への指示として読まれ続けるので、残さない。`.git/harness-doc/` は作業の途中の控えで、消してよい。
再起動は要らない。外し終えると、プロジェクトに `docs-style/` と `.claude/doc-harness.config.json` が無くなっている。

### 2. マシンから外す

すべてのプロジェクトで上の「1. 各プロジェクトから外す」を済ませてから、次のように頼む。

```text
次のコマンドを実行して。
claude plugin uninstall harness-doc@doc-harness --scope user
claude plugin marketplace remove doc-harness
```

外したら Claude Code を再起動する（導入の手順「2. Claude Code を再起動する」と同じ操作）。「`claude plugin list` を実行して」と頼み、`harness-doc` が出なければ外れている。
