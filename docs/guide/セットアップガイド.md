# ハーネスを自分のプロジェクトに導入する

<!-- doc-type: howto -->

## この文書でできること

Claude Code を使っているプロジェクトに `harness-doc` を導入し、`/harness-doc:manual-writer` を
呼べる状態と、`.md` を書くと `check-docs` フックが検査する状態にできる。所要10分、全5手順。

読者: Claude Code を日常的に使っていて、プラグインを入れたことがある開発者。
`claude` と `git` を bash（Windows では Git Bash）で使える前提。

この文書での呼び方: **ハーネス**はリポジトリ `claude-doc-harness` 全体を指す。
そのうち Claude Code にプラグインとして入る部分が **`harness-doc`** である。

## 前提条件

- Claude Code がインストールされ、ターミナルで `claude --version` がバージョンを返す
- Node.js がインストールされている（確認: `node --version`）。フックと `tools/apply.mjs` が使う。
  動作を確認したのは v24.12.0 と、CI の v22。それより古い版は未確認
- 導入先のプロジェクトのパスが分かっている（例: `D:/Develop/Web/my-app`。bash ではスラッシュ区切りで書く）
- GitHub（`github.com/mizuta0711/claude-doc-harness`）に到達できる

## 手順

### 1. マーケットプレイスを登録する（初回だけ）

```bash
claude plugin marketplace add mizuta0711/claude-doc-harness
```

期待される出力（末尾）:

```text
✔ Successfully added marketplace: doc-harness (declared in user settings)
```

既に登録済みの場合も、そのまま次へ進んでよい。

### 2. プラグインを入れる

```bash
claude plugin install harness-doc@doc-harness --scope user
```

期待される出力:

```text
✔ Successfully installed plugin: harness-doc@doc-harness (scope: user)
```

`--scope user` は、このマシンの全プロジェクトで使う指定。プロジェクトごとに版を固定したいときは
`--scope project` にし、**導入先のプロジェクトのディレクトリで**実行する（記録先がそのプロジェクトの
`.claude/settings.json` になる）。どちらで入れたかを後から読み取れるように、`--scope` は省略せずに書く。

うまくいかない場合: `not found in marketplace` が出たら手順1が済んでいない。手順1に戻る。

### 3. ハーネスのリポジトリを手元に置く

手順4のスクリプトを使うために clone する。置き場所はどこでもよい。例として `D:/Develop` に置く。

```bash
git clone https://github.com/mizuta0711/claude-doc-harness.git D:/Develop/claude-doc-harness
```

期待される状態: `D:/Develop/claude-doc-harness/tools/apply.mjs` が存在する。

既に clone 済みなら、そのディレクトリで `git pull` だけ実行する。
ただし `git pull` しても、導入先に既に置いたファイルは手順4で上書きされない。
テンプレートの更新を取り込むときは、差分を手で反映する。

### 4. プロジェクト側のファイルを置く

**プラグインでは配れないファイルを、導入先のプロジェクトに置く。**
プラグインはスキル・エージェント・フックしか配れず、プロジェクトの `CLAUDE.md` を書き換えられない。
また用語集と設定はプロジェクトごとに編集して育てるものなので、プロジェクト側に置く。置くものは次の3つ。

- `.claude/doc-harness.config.json`: フックの検査対象の設定。**このファイルが無いと、フックは何も検査しない**
- `docs-style/`: 用語集・曖昧語リスト・使い方の1ページ
- `CLAUDE.md` の「文書ルール（harness-doc）」の節: Claude に、文書を書く前にスキルを使わせる指示

手順3で clone したディレクトリで実行する。`<プロジェクト>` は導入先のパスに置き換える。
パスはスラッシュ区切りで書く（`D:/Develop/Web/my-app`）。バックスラッシュのまま書くと、bash が消してしまい別のパスになる。

```bash
cd D:/Develop/claude-doc-harness
node tools/apply.mjs --dest <プロジェクト>
```

期待される出力:

```text
  コピー   .claude/doc-harness.config.json
  新規    CLAUDE.md
  コピー   docs-style/banned-words.txt
  コピー   docs-style/glossary.md
  コピー   docs-style/README.md

次の手順:
  1. claude plugin marketplace add mizuta0711/claude-doc-harness   （初回だけ）
  2. claude plugin install harness-doc@doc-harness --scope user
  3. Claude Code を再起動する
  4. docs-style/README.md を読む
```

`CLAUDE.md` の行は次の3通りになる。

| 導入先の状態 | 表示 |
|---|---|
| `CLAUDE.md` が無い | `新規` |
| `CLAUDE.md` があり、文書ルールの節が無い | `追記`（末尾に節を足す） |
| `CLAUDE.md` に文書ルールの節が既にある | `スキップ` |

`CLAUDE.md` 以外で同名のファイルが既にある行は `スキップ` と出て、**上書きしない**。
末尾の「次の手順」の1と2は、この文書の手順1・2で済んでいるので飛ばす。
何が起きるかを先に見たいときは `--dry-run` を付ける（何も書き込まない）。

### 5. Claude Code を再起動する

開いている Claude Code を終了し（`/exit`）、導入先のプロジェクトで開き直す。
プラグインのスキルとフックは再起動後に有効になる。

## 確認

1. `claude plugin list` を実行し、`harness-doc@doc-harness` の項目があること。
   判断するのは `Status: ✔ enabled` の行だけ。`Scope` は手順2で指定した値、`Version` は導入した時点の版になる

   ```text
     ❯ harness-doc@doc-harness
       Version: 0.1.0
       Scope: user
       Status: ✔ enabled
   ```

2. Claude Code で `/harness-doc:manual-writer` とだけ入力する。スキルが起動し、文書の読者とゴールを尋ねてくれば成功。
   確認が済んだら Esc キーで中断してよい
3. Claude Code に「`docs/test.md` に `必要に応じて再起動する。` の1行だけを、言い換えずにそのまま書いて」と頼む。
   書き込みの直後に、Write ツールの結果の下へ `PostToolUse` フックの出力として指摘が表示される。次の行が含まれていれば成功

   ```text
     L1    曖昧語「必要に応じて」: 条件と値を具体的に書く
   ```

   導入先に markdownlint / textlint が入っていると、それらの指摘も加わって件数が増える。
   指摘は Claude にも渡るので、Claude が続けてファイルを直すことがある。**これは失敗ではない。** 表示された指摘の行で判断する。
   Claude が最初から文を言い換えて書き、指摘が一度も出ない場合は、「言い換えずに」と念を押して頼み直す。
   ファイルは `docs/` の下に書かせる（`docs/` の外は既定の検査対象外）

確認が済んだら `docs/test.md` は消す。

## うまくいかない場合

| 症状 | 原因 | 対処 |
|---|---|---|
| `/harness-doc:manual-writer` が `Unknown skill` | 再起動していない | 手順5をやり直す |
| 再起動しても Windows の VS Code 拡張だけで `Unknown skill` | `--scope project` で入れたとき、拡張がプロジェクトパスのドライブレターの大小を区別してしまう既知の不具合（[anthropics/claude-code#74912](https://github.com/anthropics/claude-code/issues/74912)） | `--scope project` で入れていたら、外して `--scope user` で入れ直す。`--scope user` で入れていたら、ターミナルの `claude` で使う |
| フックが何も言わない | 次の順に確かめる。(1) 再起動していない (2) `.claude/doc-harness.config.json` が無い（設定不在は素通りする） (3) `node --version` が通らない（フックは Node で動く） | (1) 手順5 (2) 手順4 (3) Node.js を入れて PATH を通し、再起動する |
| `docs/` 以外のファイルでフックが何も言わない | 既定の `include` は `docs/**/*.md` と `README.md` だけ | `.claude/doc-harness.config.json` の `include` に足す（例: `"guides/**/*.md"`）。使える記法は `**`・`*`・`?` だけ（[check-docs 仕様](../reference/check-docs仕様.md)） |
| `apply.mjs` が `dest が存在しません` | パスの誤り。バックスラッシュ区切りで書くと bash が消す | スラッシュ区切りに直し、同じパスを `ls` に渡して存在を確かめる |

## 取り外し

入れたときと同じ `--scope` を指定する。

```bash
claude plugin uninstall harness-doc@doc-harness --scope user
```

プロジェクト側のファイルは手で消す。

- `CLAUDE.md` の「文書ルール（harness-doc）」の節: **プラグインを外しても Claude への指示として残る。**
  ルールを外したいなら消す
- `docs-style/` と `.claude/doc-harness.config.json`: プラグインが無ければ読まれないので、残しても動作に影響しない

完全に元へ戻すなら、マーケットプレイスの登録も消し、手順3で clone したディレクトリを削除する。

```bash
claude plugin marketplace remove doc-harness
```
