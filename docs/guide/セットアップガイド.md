# ハーネスを自分のプロジェクトに導入する

<!-- doc-type: howto -->
<!-- この文書は manual-writer の手順で書いたサンプル文書（受け入れ基準5）。読者役レビューと check-docs を通している -->

## この文書でできること

Claude Code を使っているプロジェクトに `harness-doc` を導入し、`/harness-doc:manual-writer` を
呼べる状態と、`.md` を書くと `check-docs` フックが検査する状態にできる。所要10分、全4手順。

読者: Claude Code を日常的に使っていて、プラグインを入れたことがある開発者（プロファイル: developer）。
`claude` コマンドをターミナルで打てる前提。

## 前提条件

- Claude Code がインストールされ、ターミナルで `claude --version` がバージョンを返す
- Node.js 22 以上（確認: `node --version` が `v22.` 以上を返す）。フックと `apply.mjs` が使う
- 導入先のプロジェクトのパスが分かっている（例: `D:\Develop\Web\my-app`）
- このリポジトリを clone 済み、または GitHub（`mizuta0711/claude-doc-harness`）に到達できる

## 手順

### 1. マーケットプレイスを登録する（初回だけ）

```bash
claude plugin marketplace add mizuta0711/claude-doc-harness
```

期待される出力:

```text
Successfully added marketplace: doc-harness
```

既に登録済みなら `already exists` を含むメッセージが出る。そのまま次へ進んでよい。

### 2. プラグインを入れる

```bash
claude plugin install harness-doc@doc-harness --scope user
```

期待される出力:

```text
Successfully installed plugin: harness-doc@doc-harness
```

`--scope user` はこのマシンの全プロジェクトで使う指定。プロジェクトごとに版を固定したいときだけ
`--scope project` にする。**`--scope` を省略しない**（省略時の既定は `user` だが、選んだことにならない）。

うまくいかない場合: `not found in marketplace` が出たら手順1が済んでいない。手順1に戻る。

### 3. テンプレート層をプロジェクトへ置く

このリポジトリのルートで実行する。`<プロジェクト>` は導入先のパスに置き換える。

```bash
node tools/apply.mjs --dest <プロジェクト>
```

期待される出力（新規導入の場合）:

```text
  追記    CLAUDE.md
  コピー  .claude/doc-harness.config.json
  コピー  docs-style/README.md
  コピー  docs-style/banned-words.txt
  コピー  docs-style/glossary.md

次の手順:
  1. claude plugin marketplace add mizuta0711/claude-doc-harness   （初回だけ）
  ...
```

既に同名のファイルがある行は `スキップ` と出て、**上書きしない**。`CLAUDE.md` は末尾に
「文書ルール（harness-doc）」の節を追記する（既にあれば `スキップ`）。
先に何が起きるか見たいときは `--dry-run` を付ける。

### 4. Claude Code を再起動する

開いている Claude Code を終了し（`/exit`）、プロジェクトで開き直す。
プラグインのスキルとフックは再起動後に有効になる。

## 確認

1. `claude plugin list` を実行し、出力に `harness-doc` の行があること
2. Claude Code で `/harness-doc:manual-writer` と入力し、スキルが起動すること（引数なしなら読者とゴールを尋ねてくる）
3. プロジェクトの `docs/` に、曖昧語を含む `.md` を Claude Code に書かせる。
   例: 「docs/test.md に`必要に応じて再起動する`とだけ書いて」。
   フックが次の指摘を出し、Claude が直そうとすれば動いている

```text
[check-docs] docs/test.md に 1 件の指摘があります。直してから先へ進んでください。
  L1   曖昧語「必要に応じて」: 条件と値を具体的に書く
```

確認が済んだら `docs/test.md` は消す。

## うまくいかない場合

| 症状 | 原因 | 対処 |
|---|---|---|
| `/harness-doc:manual-writer` が `Unknown skill` | 再起動していない | 手順4をやり直す |
| 同上（Windows + VS Code 拡張） | プロジェクトパスのドライブレターの大小を拡張が吸収しない既知の不具合（dev-harness の README に記載） | `--scope user` で入れる。CLI（ターミナルの `claude`）では起きない |
| フックが何も言わない | `.claude/doc-harness.config.json` が無い。設定不在は素通りする | 手順3をやり直す |
| フックが `docs/` 以外のファイルで何も言わない | `include` が `docs/**/*.md` と `README.md` だけ | `.claude/doc-harness.config.json` の `include` に加える |
| `apply.mjs` が `dest が存在しません` | パスの誤り | `--dest` のパスを `ls` で確かめる |

## 取り外し

```bash
claude plugin uninstall harness-doc@doc-harness --scope user
```

プロジェクト側の `docs-style/`・`.claude/doc-harness.config.json`・`CLAUDE.md` の節は手で消す。
消さなくても害は無い（プラグインが無ければフックもスキルも動かない）。
