# ハーネスを自分のプロジェクトに導入する

<!-- doc-type: howto -->

## この文書でできること

Claude Code を使っているプロジェクトに文書ハーネスを導入し、「〇〇の手順書を書いて」と頼むだけで
決まった手順・読者役レビュー・機械チェックを通した文書が出てくる状態にできる。
**利用者はコマンドを打たない。** すべて Claude Code に日本語で頼む。所要5分、全3手順。

読者: Claude Code を日常的に使っている人。プラグインの仕組みを知らなくてよい。

この文書での呼び方: **ハーネス**はリポジトリ `claude-doc-harness` 全体を指す。
そのうち Claude Code にプラグインとして入る部分が **`harness-doc`** である。

## 前提条件

- Claude Code が動いている
- Node.js がインストールされている。フックが使う。Claude Code に「`node --version` を実行して」と頼み、
  `v` で始まる版番号が返れば入っている。動作を確認したのは v24.12.0 と v22。それより古い版は未確認
- Claude Code から GitHub（`github.com/mizuta0711/claude-doc-harness`）に到達できる

## 手順

### 1. プラグインを入れる（このマシンで1回だけ）

どのプロジェクトで開いた Claude Code でもよい。次の文をそのまま貼って頼む。

```text
次の2つのコマンドを実行して、文書ハーネスのプラグインを入れて。
claude plugin marketplace add mizuta0711/claude-doc-harness
claude plugin install harness-doc@doc-harness --scope user
```

期待される結果: Claude Code が2つを実行し、出力に次の2行が含まれる。

```text
✔ Successfully added marketplace: doc-harness (declared in user settings)
✔ Successfully installed plugin: harness-doc@doc-harness (scope: user)
```

1行目は、既に登録済みなら別のメッセージになる。2行目が出ていれば先へ進んでよい。

`--scope user` は、このマシンの全プロジェクトで使う指定。プロジェクトに設定ファイルが無ければ
ハーネスは何もしないので、全プロジェクトに入れても他の作業の邪魔にはならない。

うまくいかない場合: 2行目の代わりに `not found in marketplace` が出たら、1つ目のコマンドが失敗している。
Claude Code に1つ目のエラーを見せてもらう。

### 2. Claude Code を再起動する

開いている Claude Code を終了し（`/exit`）、導入したいプロジェクトで開き直す。
プラグインは再起動後に読み込まれる。

### 3. プロジェクトに導入する（プロジェクトごとに1回だけ）

導入したいプロジェクトで開いた Claude Code に頼む。

```text
このプロジェクトに文書ハーネスを入れて
```

`setup-project` スキルが起動し、次の3つを置く。

| 置くもの | 役割 |
|---|---|
| `CLAUDE.md` の「文書ルール（harness-doc）」の節 | Claude に、文書を書く前に決まった手順を踏ませる。`CLAUDE.md` が無ければ新規に作り、あれば末尾に足す |
| `docs-style/` | 用語集・曖昧語リスト・使い方の1ページ。プロジェクトごとに育てる |
| `.claude/doc-harness.config.json` | 検査対象の設定。**これが無いと、フックは何も検査しない** |

期待される結果: 完了報告の表が出て、「置いたもの」に上の3つが並ぶ。
**既にあるファイルは上書きしない。** 2回目に頼むと、すべて「触らなかったもの」に並ぶ。

claude-dev-harness を導入済みのプロジェクトでは、報告に「dev-harness 併用」と出る。
`docs/設計書/`・`docs/features/`・`docs/reviews/`・`docs/handoff/` は検査対象から自動で外れ、
従来どおり harness-core が扱う。残りの `docs/` 配下（利用マニュアル・運用手順）と `README.md` が対象になる。

この手順は再起動なしで有効になる。

## 確認

Claude Code に次の文をそのまま頼む。

```text
docs/test.md に「必要に応じて再起動する。」の1行だけを、言い換えずにそのまま書いて。フックの指摘が出たら、その指摘をそのまま見せて
```

指摘に次の行が含まれていれば成功。

```text
  L1    曖昧語「必要に応じて」: 条件と値を具体的に書く
```

指摘は Claude にも渡るので、Claude が続けてファイルを直すことがある。**これは失敗ではない。**
Claude が最初から言い換えて書き、指摘が一度も出ない場合は、「言い換えずに」と念を押して頼み直す。

確認が済んだら「docs/test.md を消して」と頼む。

## うまくいかない場合

| 症状 | 原因 | 対処 |
|---|---|---|
| 手順3で頼んでも「setup-project というスキルは無い」と返る | 再起動していない、または手順1が失敗している | 手順2をやり直す。直らなければ「`claude plugin list` を実行して」と頼み、`harness-doc` の行に `Status: ✔ enabled` があるか見る |
| Windows の VS Code 拡張だけでスキルが見つからない | `--scope project` で入れたとき、拡張がプロジェクトパスのドライブレターの大小を区別してしまう既知の不具合（[anthropics/claude-code#74912](https://github.com/anthropics/claude-code/issues/74912)） | 手順1のとおり `--scope user` で入れる。それでも起きる場合は、ターミナルの `claude` で使う |
| 確認で指摘が出ない | (1) 手順3が済んでいない (2) `docs/` の外に書かせた (3) Node.js が入っていない | (1) 手順3を頼む (2) `docs/` の下に書かせる (3) 前提条件の確認をする |
| 設計書を頼んだら「対象外」と言われる | claude-dev-harness の設計書は harness-core が扱う | 正常。設計書は従来どおり harness-core の `update-docs` で頼む |
| `docs/` 以外の文書も検査してほしい | 既定の検査対象は `docs/` 配下と `README.md` だけ | 「`guides/` 配下も検査対象に入れて」のように頼む。Claude が設定ファイルの `include` に足す |

## 取り外し

プロジェクトから外すときは、そのプロジェクトで頼む。

```text
このプロジェクトから文書ハーネスを外して。CLAUDE.md の「文書ルール（harness-doc）」の節、docs-style/、.claude/doc-harness.config.json を消して
```

`CLAUDE.md` の節は、プラグインを外しても Claude への指示として残る。ルールを外したいなら必ず消す。

このマシンから完全に外すときは、次のように頼む。

```text
次のコマンドを実行して。
claude plugin uninstall harness-doc@doc-harness --scope user
claude plugin marketplace remove doc-harness
```
